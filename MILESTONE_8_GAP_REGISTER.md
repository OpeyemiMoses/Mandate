| **GAP-01** | Decentralized & Inconsistent OutLayer Transfer Invocations | **HIGH** | `src/app/api/tasks/route.ts`<br>`src/app/api/tasks/[id]/route.ts`<br>`src/lib/agent/procurementAgent.ts`<br>`src/app/api/wallets/withdraw/route.ts`<br>`src/lib/integrations/adapters/nearAdapter.ts` | `executeOutlayerTransfer` was called directly across multiple routes and agent routines, bypassing centralized CAS budget authority and unified validation. | Centralized all transfer operations under `ExecutionBoundaryService`. | **GAP-02** | Absence of Cryptographic Execution Authorization Envelope | **CRITICAL** | `src/lib/governance/approvalManager.ts`<br>`src/lib/coordination/financialCoordinator.ts`<br>`src/app/api/approvals/route.ts` | Operations proceeded from policy/approval to execution without a cryptographically signed authorization envelope binding the exact execution parameters. | Implemented `ExecutionAuthorizationService` generating HMAC-SHA256 envelopes containing unique execution ID, nonce, canonical parameters, policy/mandate versions, and short expiration (5 minutes). Single-use nonces are recorded in the database and atomically consumed. | Verified in `tests/milestone-8-execution-security.ts` Cases 6, 7, 8, 9 and `tests/live-near-testnet-verification.ts` Stages 5, 6, 7. Tampering and replays strictly rejected. | **RESOLVED** |
| **GAP-03** | Premature Transaction Status Settlement & Mock Hash Leaks | **HIGH** | `src/app/api/approvals/route.ts`<br>`src/app/api/tasks/route.ts`<br>`src/lib/coordination/financialCoordinator.ts` | Transactions were immediately recorded as `status: "CONFIRMED"` upon HTTP 200 from OutLayer or fell back to mock hashes (`mock-tx-...`) without verifying on-chain block inclusion. | Implemented strict 10-stage execution lifecycle (`PROPOSED` $\rightarrow$ `VALIDATED` $\rightarrow$ `AUTHORIZED` $\rightarrow$ `SIGNED` $\rightarrow$ `BROADCAST` $\rightarrow$ `CONFIRMING` $\rightarrow$ `CONFIRMED` or `REQUIRES_RECOVERY`). Live on-chain execution strictly halts if wallet is unfunded without fabricating mock hashes. | Verified in `tests/milestone-8-execution-security.ts` Cases 12, 14, 22, 23 and `tests/live-near-testnet-verification.ts` Stages 3, 8. | **RESOLVED** |
| **GAP-04** | Dangerous Reservation Release on Ambiguous Network Timeouts | **CRITICAL** | `src/lib/coordination/financialCoordinator.ts`<br>`src/app/api/approvals/route.ts` | Catch blocks immediately released budget reservations (`releaseMandateBudgetAtomic`) on exception. An RPC timeout after network broadcast causes funds to be released while the transfer settles on-chain, leading to double-spending. | Enforced the golden rule: **Never release a financial reservation simply because an RPC request timed out.** Implemented `ExecutionRecoveryService.classifyFailure`: pre-broadcast failures release immediately, while post-broadcast ambiguous timeouts retain reservations, transition to `REQUIRES_RECOVERY`, and poll NEAR RPC before settlement. | Verified in `tests/milestone-8-execution-security.ts` Cases 14, 15, 22, 23. | **RESOLVED** |
| **GAP-05** | Incomplete Pre-Execution NEAR Transaction Validation | **HIGH** | `src/lib/outlayer.ts`<br>`src/app/api/approvals/route.ts`<br>`src/app/api/tasks/route.ts` | No rigorous preflight checks for NEAR recipient format (implicit 64-hex vs `.testnet`/`.near`), active account status, minimum storage reserve, or balance sufficiency before invoking OutLayer. | Implemented `ExecutionValidationService` with deterministic checks for NEP-0145 account regex, integer-only amount syntax (rejecting floats), exact `BigInt` yoctoNEAR arithmetic, 0.05 NEAR storage reserve buffer, mandate threshold limits, and live RPC balance verification. | Verified in `tests/milestone-8-execution-security.ts` Cases 1, 2, 3, 4, 5. | **RESOLVED** |
| **GAP-06** | Inadequate Idempotency & Replay Protection Across Services | **HIGH** | `src/app/api/tasks/route.ts`<br>`src/app/api/approvals/route.ts` | Replay attacks or concurrent duplicate requests with differing payloads were not systematically rejected; authorization tokens could potentially be replayed if not tracked with single-use state. | Implemented `ExecutionIdempotencyService` storing canonical payload hashes and enforcing single-use nonce tracking. Identical requests return prior execution; parameter tampering under the same idempotency key is rejected with `PARAMETER_DRIFT`. | Verified in `tests/milestone-8-execution-security.ts` Cases 10, 11 and `tests/live-near-testnet-verification.ts` Stage 7. | **RESOLVED** |
| **GAP-07** | OutLayer TEE Security Boundary & Credential Isolation | **MEDIUM** | `src/lib/outlayer.ts`<br>`src/lib/walletInitialization.ts` | OutLayer API keys were stored in plaintext in the DB; while not exposed to the LLM or frontend, they lacked a dedicated service layer boundary preventing arbitrary internal usage. | Isolated OutLayer API key handling strictly inside `ExecutionBoundaryService` server-side context. Keys and signatures are scrubbed before storage, display, or model context. Fallback stub vault allows offline resilience. | Verified in `tests/milestone-8-execution-security.ts` Case 20 and `tests/live-near-testnet-verification.ts` Stage 1. | **RESOLVED** |
| **GAP-08** | Incomplete Execution Lifecycle Event Types in SHA-256 Audit Chain | **MEDIUM** | `src/lib/auditLedger.ts` | The audit chain recorded general events but lacked specific lifecycle events (`EXECUTION_PROPOSED`, `EXECUTION_AUTHORIZED`, `TRANSACTION_BROADCAST`, `EXECUTION_RECOVERED`, etc.). | Defined `EXECUTION_AUDIT_EVENTS` covering 14 distinct lifecycle events in `auditLedger.ts`. Every execution transition from `PROPOSED` to `RECOVERED` appends an immutable record with previous event hash linkage and payload digest. | Verified in `tests/milestone-8-execution-security.ts` Case 24 and `tests/live-near-testnet-verification.ts` Stage 9 (100% unbroken cryptographic chain). | **RESOLVED** |
